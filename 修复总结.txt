  AI决策流程（三步法）
───────────────────────────────────────────────────────────────

第1步：理解用户意图
  - "开始测试" → 明确，调用 start_guided_test
  - "测试" → 不明确，调用 ask_clarification
  - "为什么古人喜欢玉" → 闲聊，不调用工具

第2步：检查前置条件
  - 生成玉 → 需要先完成测试
  - 保存到展厅 → 需要先生成图片

第3步：返回工具调用
  - 可以一次返回多个工具
  - 没有操作时返回空数组
  - 闲聊时必须返回空数组

  问题描述
───────────────────────────────────────────────────────────────

用户说"开始与玉对话"，语音识别将"玉"误识别为"域"。
导致AI无法理解用户意图，交互失败。

实际案例：
  用户说: "开始与玉对话"
  识别为: "开始与域对话"
  AI回复: 无法理解"域"的含义

───────────────────────────────────────────────────────────────
  解决方案
───────────────────────────────────────────────────────────────

✅ 在 voiceStore.js 中添加 correctTranscript() 方法
✅ 在语音识别结果返回后、发送给AI之前自动修正
✅ 采用上下文优先的修正策略
✅ 添加调试日志，方便追踪修正效果

───────────────────────────────────────────────────────────────
  技术实现
───────────────────────────────────────────────────────────────

【新增方法】correctTranscript(text)
  - 修正常见的玉文化相关误识别
  - 优先匹配完整短语，避免误修正
  - 输出调试日志

【修改位置】
  1. init() 中的 recognition.onresult
  2. recognizeOnce() 中的 recognition.onresult

【修正规则】
  与域对话 → 与玉对话
  和域对话 → 和玉对话
  跟域对话 → 跟玉对话
  域对话 → 玉对话
  开始与域 → 开始与玉
  生成域 → 生成玉
  生成我的域 → 生成我的玉
  匹配域 → 匹配玉
  古域 → 古玉
  遇见/预见/御/育 → 玉

───────────────────────────────────────────────────────────────
  修正策略
───────────────────────────────────────────────────────────────

【上下文优先】
  1. 先匹配完整短语（如"与域对话"）
  2. 再匹配单字（如"域"）
  3. 避免误修正正常使用"域"字的场景

【调试日志】

  问题描述
───────────────────────────────────────────────────────────────

用户说"聊聊"、"对话"、"与玉对话"时，AI没有跳转到对话页。
AI只是在当前页面闲聊，没有调用 navigate 工具。

实际案例：
  用户: "聊聊"
  AI: "哈哈，想聊啥都行！你匹配的是良渚神人兽面玉琮..."
  结果: ❌ 停留在结果页，纯闲聊

预期行为：
  用户: "聊聊"
  AI: "好嘞！咱们去对话页深度聊聊～"
  结果: ✅ 自动跳转到 /chat 对话页

───────────────────────────────────────────────────────────────
  根本原因
───────────────────────────────────────────────────────────────

虽然系统中已经有 navigate 工具可以跳转到 /chat 页面，但是：

1. 后端系统提示词中没有明确告诉AI什么时候应该跳转到对话页
2. 前端工具定义中 navigate 工具的使用场景没有包含"对话"相关的关键词
3. 决策流程中没有"与玉对话"的示例

导致AI无法识别用户想要进入对话页的意图。

  解决方案
───────────────────────────────────────────────────────────────

✅ 1. 更新后端系统提示词

───────────────────────────────────────────────────────────────
  问题描述
───────────────────────────────────────────────────────────────

玉灵童子面板界面过长，包含太多内容：
  • 设置项直接展示（自动跳转、隐私模式、语音播报等）
  • 长期记忆区域直接展示
  • 导致面板滚动过长，用户体验不佳

用户反馈：
  "玉灵童子界面太长了，帮我把长期记忆收起来，不给用户看，
   然后自动跳转到下一步隐私模式（不保存记忆）自动语音播报
   空闲时主动闲聊声线角色这些放到设置里面"

───────────────────────────────────────────────────────────────
  解决方案
───────────────────────────────────────────────────────────────

✅ 1. 设置区域折叠化
   - 将所有设置项放入可折叠的"设置"区域
   - 默认收起，点击展开
   - 包含：自动跳转、隐私模式、自动语音播报、空闲闲聊、声线角色

✅ 2. 长期记忆折叠化
   - 将长期记忆区域改为可折叠
   - 默认收起，点击展开
   - 在标题显示记忆数量，如"长期记忆 (5)"

✅ 3. 界面更简洁
   - 默认只显示核心功能：对话历史、语音输入、文字输入
   - 高级功能收起，需要时展开
   - 减少滚动，提升用户体验
