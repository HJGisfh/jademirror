# 🧪 玉灵童子 AI决策测试用例

## 测试目的

验证AI能够正确理解用户意图，并调用合适的工具。

---

## ✅ 测试用例

### 用例1：明确开始测试

**场景**: 用户在首页，想开始测试

**输入**:
```
用户: "开始测试"
当前页面: home
```

**期望输出**:
```json
{
  "reply": "哇，这就来了！超期待带你找到你的本命古玉！走，咱们开始测试~",
  "tool_calls": [
    {"name": "navigate", "args": {"route": "/test"}},
    {"name": "start_guided_test", "args": {}}
  ]
}
```

**验证点**:
- ✅ AI理解了"开始测试"的意图
- ✅ 调用了navigate跳转到测试页
- ✅ 调用了start_guided_test开始测试
- ✅ 回复语气活泼友好

- ✅ 使用ask_clarification询问

## 🔍 测试方法

### 方法1：手动测试

1. 启动项目
2. 打开浏览器
3. 依次输入测试用例中的用户输入
4. 观察AI的回复和执行的操作
5. 对比期望输出

### 方法2：查看日志

1. 打开浏览器开发者工具（F12）
2. 查看Console标签
3. 观察API请求和响应
4. 验证tool_calls是否正确

### 方法3：后端日志

2. 观察AI返回的JSON

## ⚠️ 常见问题

### Q1: AI没有调用工具
**可能原因**:
- 后端返回的格式不对
- tool_calls字段缺失
- AI没有理解意图

**解决方案**:
- 检查后端日志
- 查看API响应格式
- 优化系统提示词

### Q2: AI调用了错误的工具
**可能原因**:
- 工具定义不清晰
- 上下文信息不足
- AI理解偏差

**解决方案**:
- 完善工具描述
- 提供更多上下文
- 添加使用示例

### Q3: AI总是询问澄清
**可能原因**:
- 系统提示词过于保守
- 工具定义过于复杂

**解决方案**:
- 调整提示词
- 简化工具定义
- 提供更多示例
